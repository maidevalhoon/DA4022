Project Title: Optimizing LLM Memory and Compute Allocation using SemanticDPP Uncertainty Quantification Total Marks: 40
1. Abstract & Motivation (5 Marks)
Large Language Models (LLMs) often generate text with varying degrees of confidence, sometimes responding to prompts confidently with confabulations, fabrications, and "hallucinations". Dynamically allocating memory resources—such as KV cache size, retrieved context windows (RAG), or cascading to larger models—based on the model's internal uncertainty can drastically optimize inference efficiency. This project proposes a system that dynamically allocates computational memory based on the real-time uncertainty of the model, utilizing the highly efficient SemanticDPP framework detailed in the reference document "9298_SemanticDPP_Efficient_Unc.pdf".
2. Problem Statement (5 Marks)
Current LLM deployment strategies often allocate a fixed memory footprint (e.g., maximum context length, fixed beam search width, or static RAG retrieval limits) regardless of the query's complexity. This leads to wasted memory for simple queries and insufficient memory for highly ambiguous queries. The objective of this project is to develop an adaptive memory allocation controller that measures the uncertainty corresponding to the semantic variation in outputs of a large language model based on internal activations.
3. Methodology & Core Architecture (15 Marks)
The system will act as a middleware controller intercepting LLM generation to dynamically adjust memory limits. The architecture is built directly on the methodology from "9298_SemanticDPP_Efficient_Unc.pdf":
Embedding Extraction & Semantic Representation: For a given prompt, the system will sample multiple responses and extract their corresponding embedding vectors. To measure semantic similarity, a function maps the d-dimensional embedding vector to a p<d dimensional semantically meaningful subspace.
Kernel Computation: The similarity between two embedding vectors xi​ and xj​ is computed using the covariance function k(xi​,xj​)=exp(−α∣∣ϕ(xi​)−ϕ(xj​)∣∣2).
Uncertainty Quantification (SemanticDPP): The system uses determinantal point processes (DPPs) to learn a model over semantic (dis)similarity in model embeddings. The uncertainty of a set of responses S is calculated using the log-determinant of the kernel sub-matrix: log P(S)=log det KS​.
Memory Allocation Policy:
Low Uncertainty (High Confidence): The model is highly likely to answer correctly. The system allocates minimal memory (e.g., restricts KV cache, uses greedy decoding, and prevents RAG activation).
High Uncertainty (Low Confidence): The risk of hallucinating is high. The system aggressively allocates memory by expanding the context window, triggering a dense retrieval (RAG) process, or routing the query to a higher-capacity model (e.g., cascading from a 9B to a 27B parameter model).

Phase 2: Controller Logic: Build the thresholding logic. By varying the threshold, we can trace out precision-recall and ROC curves to find the optimal memory-trigger point.
Phase 3: Benchmarking: Evaluate the adaptive memory system on standard QA datasets such as TruthfulQA, GSM8k, and TriviaQA.
Metrics: The primary evaluation metrics will be Area Under the ROC curve (AUROC) for uncertainty detection, alongside quantitative measurements of peak memory reduction (in MB/GB) and inference latency (in seconds).

Response: Static Memory Footprint: Reserving the exact same amount of computer memory (RAM or GPU space) for every single prompt. It is like renting a 50-seater bus for every trip, regardless of whether you are transporting a football team or just going to the grocery store alone.
Context Length: The maximum amount of text (tokens) the AI can hold in its short-term memory at one time to process a prompt.
Beam Width (Beam Search): A generation technique where the AI considers multiple different word paths at the same time before choosing the best final sentence. A "wider" beam explores more possibilities but burns much more memory and computing power.
Retrieval Limits: In systems where the AI searches external documents to find answers (RAG, or Retrieval-Augmented Generation), this is the hard cap on how many paragraphs or pages it is allowed to pull into its memory.
Confabulations / Hallucinations: When an AI does not know the answer but confidently fabricates fake facts, fake citations, or erroneous information instead of admitting it does not know.
Uncertainty Quantification: The mathematical process of peeking inside the AI's internal state to measure how "unsure" or "confused" it actually is, regardless of how confident its generated text sounds.
Dynamic Allocation Controller: A piece of software that acts as a smart traffic cop, instantly increasing or decreasing the computing power and memory given to the AI based on what is happening in real-time.
The Problem Statement, Simplified
Right now, running large language models is highly inefficient. System administrators give the AI a massive, fixed amount of memory and processing power for every single question. If you ask an AI, "What is 2+2?", it locks up the same expensive computing resources as it would if you asked it to "Summarize this 50-page legal contract." This wastes massive amounts of hardware power on simple tasks. Conversely, when you ask a highly complex or ambiguous question, that fixed memory limit might not be enough. When the AI runs out of resources to figure out a hard problem, it simply makes up a fake answer (hallucinates) to end the process.
Your project is to build a smart resource manager. You will write a program that constantly measures the AI's internal confusion (uncertainty) as it reads a prompt.
If your program sees the AI is highly confident and the question is easy, it restricts the AI to minimal memory and computing power to save resources. If your program detects that the AI is highly uncertain and at risk of hallucinating, it instantly unlocks more resources—expanding the context window, letting it search external databases, or giving it more time to think.

Response: Project Overview & Motivation
Standard Large Language Model (LLM) deployments assign fixed computational resources—such as maximum Key-Value (KV) cache allocations, full context windows, and static generation budgets—irrespective of input difficulty. This design wastes memory and compute on straightforward prompts while providing insufficient capacity for ambiguous or knowledge-intensive queries, often resulting in confabulations and hallucinations. By leveraging uncertainty quantification to detect knowledge boundaries, this project introduces an adaptive controller that dynamically scales memory and compute allocations at inference time.
Problem Formulation & Objectives
The objective is to formulate an adaptive memory allocation pipeline that evaluates model uncertainty to optimize runtime efficiency without degrading answer quality.
Pre-generation Knowledge Assessment: Quantify query uncertainty prior to token generation to avoid unnecessary generation compute.
Dynamic Resource Provisioning: Restrict or expand KV cache capacity and context limits dynamically based on confidence thresholds.
Selective Invocation Policy: Route high-uncertainty queries to secondary services such as dense retrieval (RAG) or model cascading.
System Architecture & Methodology
The proposed framework operates as an adaptive middleware between user input and model execution:
Uncertainty Quantification Core: The system evaluates internal model states using either a single forward pass over input tokens to extract layer-wise confidence or a Determinantal Point Process (SemanticDPP) over sampled embedding subspaces via k(xi​,xj​)=exp(−α∣∣ϕ(xi​)−ϕ(xj​)∣∣2).
Allocation Controller: Queries with uncertainty below threshold τ execute under restricted parameters using minimal KV caching and greedy decoding. Queries exceeding τ dynamically trigger context expansion, RAG injection, or escalation to a higher-capacity architecture.
Evaluation Plan & Work Breakdown
Experimental validation focuses on trade-offs between computational overhead and response quality:
Benchmark Datasets: Evaluation will run on TriviaQA and GSM8K to assess both factual recall and multi-step reasoning.
Baseline Models: Experiments will deploy lightweight models such as Phi-3-mini-4k-instruct and Llama-3.1-8B-Instruct.
Metrics: System effectiveness is quantified via Area Under the ROC Curve (AUROC) for distinguishing answerable from non-answerable queries, paired with empirical measurements of peak memory reduction and inference latency.
